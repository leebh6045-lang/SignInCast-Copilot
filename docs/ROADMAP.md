## 1. 项目定位

**SignInCast Copilot**：接在 SignInCast 课堂签到系统前面的 Agent 服务。教师用自然语言完成考勤查询、异常对账、补签处理与报告生成；模型负责理解与决策，取数、聚合、校验由代码完成，写操作必须人工确认。

一句话验收：**一位教师下课后说一句话，就能拿到"应到/实到/异常明细/建议动作 + 可贴群的报告"，且每个数字都能追溯到来源。**

## 3. 范围

### 做
- 课堂考勤运营 5 类场景：查考勤、补签对账、根因解释、报告生成、知识问答
- 教师 / 学生两种角色（学生只读本人数据）
- 工具调用、HITL、trace、评测、成本统计
- 私有化运行：OpenAI 兼容接口 + 本地 Ollama

### 不做（至少 M0–M4 内不做）
- 代签、绕过任何签到校验（合规红线）
- 人脸/指纹等生物信息
- 通知外发（短信/微信推送需要资质与额外系统）
- 多租户、计费、开放平台
- 通用 RAG 平台、Agent 市场
- **训练/微调模型**（理由见 [ADR-004](adr/004-model-strategy.md)）

## 4. 架构原则

1. **业务系统当黑盒**：只通过 REST + JWT 集成，不改 Java 工程
2. **数字来自工具**：模型不做算术，统计与校验由代码完成
3. **写操作人工确认**：模型只能"提议"，不能"执行"
4. **失败可诊断**：错误码 + trace，每一个失败都能定位
5. **预算硬约束**：步数、上下文、token、时间四道闸
6. **可替换**：模型、检索器、会话存储、状态存储都通过接口隔离

## 8. 风险登记

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 线上系统不可用/无数据 | M1 阻塞 | mock 模式 + 录制 fixture；评测用构造数据并标注 |
| 时间被其他面试打断 | 进度延误 | 里程碑"可停"设计：M1 完成即可演示 |
| 范围膨胀（想做的太多） | 永远做不完 | 锁定 5 场景 10 工具，其他进 backlog |
| LLM 成本失控 | 无法评测 | 预算硬约束 + 便宜模型开发 + 固定模型评测 |
| 过度包装（诚信） | 面试翻车 | 所有指标必须实测；局限主动写进 limitations |
