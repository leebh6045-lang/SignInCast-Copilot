# ADR-004：模型策略 —— 接现成模型，不做训练/微调

- 状态：已接受
- 日期：2026-11-17

## 背景

项目要"接入真实 AI"。同时团队/面试语境里常有人问：要不要自己训练模型？企业私有化场景还要求离线可用。需要明确：我们到底做哪一层。

## 决策

1. **通过 OpenAI 兼容接口接入现成模型**：云端（DeepSeek / 通义 / 智谱 / Kimi）或本地（Ollama / vLLM）。
2. **不做预训练、不做全参数微调**；LoRA 类微调只作为"未来可选实验"，不进主线。
3. 效果提升走**评测驱动**路线：提示词、工具 schema、few-shot、检索质量、输出校验、模型路由、缓存与裁剪。
4. M3 做**双后端对比**（云 API ↔ 本地小模型），输出质量 / 延迟 / 成本报告。

## 理由

1. **问题性质不匹配**：我们缺的不是"模型不懂考勤"，而是"模型拿不到数据、不能操作系统、输出不可靠"。这三件事由工具层、检索、校验、人工确认解决，训练模型性价比极低。
2. **成本与收益**：微调需要标注数据（我们没有）、GPU（没有）、评测集（先于训练才合理）。个人项目投入产出比差。
3. **岗位要求**：目标岗位要求 Python + LLM/Agent/RAG/Function Calling，不要求 PyTorch/训练；训练岗是另一个方向（硕博、论文、算力）。
4. **更值钱的替代方案**：模型路由（简单任务走小模型/缓存、复杂任务走强模型）、上下文裁剪、结果缓存——这正是企业"Token 成本"诉求的核心，也是目标公司 AI Compute 产品线在做的方向。
5. **没有评测集之前训练等于赌博**：无法判断微调是否真的更好，甚至可能更差。

## 后果

正面：
- 聚焦 Agent 工程能力，交付速度快
- 供应商可替换（改 `base_url` 即可），私有化只需指向本地模型
- 面试叙事清晰：做的是"应用落地层"，不是"训练层"

负面：
- 不覆盖"模型训练"能力，被问到时必须诚实说明
- 本地小模型的工具调用质量可能不足，需要评测兜底（M3 对比报告会给出结论）

## 替代方案

| 方案 | 为何不选 |
| --- | --- |
| 全参数微调开源模型 | 需 GPU 与大量标注；个人项目不现实 |
| LoRA 轻量微调 | 数据与评测集都还没有；收益不确定 |
| 本地部署 7B 并依赖它 | 工具调用稳定性存疑；先做双后端对比再决定 |
| 自己预训练小模型 | 成本与收益完全不成比例 |

## 后续

- M3：双后端对比报告（质量/延迟/成本），写入 `docs/eval-report.md`
- 若未来积累真实业务数据 + 评测集，再评估 LoRA；评估前不写任何"训练"相关表述
