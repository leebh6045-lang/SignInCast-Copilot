# ADR-005：三态传输（mock / record / live）与契约测试

- 状态：已接受
- 日期：2026-11-17

## 背景

M1 要接真实 SignInCast，但真实联调有三个约束：凭据不能进代码、线上数据不能进测试、接口结构可能变化。如果业务工具直接调 httpx，测试必须联网、演示必须有账号、契约漂移只能等运行时才发现。

## 决策

1. 业务层只依赖 `Transport` 协议，不直接使用 httpx。
2. 三种实现：
   - `MockTransport`：回放 `data/fixtures/http/*.json`，缺失即显式报错（不静默降级）
   - `RecordingTransport`：调用真实接口并落盘响应（登录响应不录制，避免落 token）
   - `LiveTransport`：真实调用，不落盘
3. 传输方式由 `COPILOT_SIGNINCAST_MODE` 控制（默认 `mock`）。
4. 契约测试遍历 fixtures，用 pydantic 模型校验每个响应结构；结构变化会让测试直接失败。
5. fixture 文件名是 `sha1("METHOD path?query")`，请求参数参与键，避免张冠李戴。

## 理由

- **测试不依赖网络与账号**：CI/本地都能跑全量测试
- **凭据安全**：登录响应不落盘，mock 模式不需要账号
- **契约可见**：接口一变，测试先红，而不是线上才发现
- **录制可迁移**：换环境重新录制即可，工具层不用改

## 后果

正面：
- 离线演示、无网评测、真实回放三种模式共存
- 契约测试成为 M1 之后每次改动的护栏

负面：
- fixtures 可能包含业务数据，需要脱敏策略（当前为合成样例 + 后续录制真实数据时人工确认）
- 录制数据会过期，需要定期重录（写进 limitations）

## 替代方案

| 方案 | 为何不选 |
| --- | --- |
| 直接 mock 函数返回值 | 测不到 HTTP 层错误码、信封结构、分页等真实行为 |
| 只写集成测试连线上 | 慢、不稳定、需要凭据、可能污染线上数据 |
| 用 vcr.py 等录制库 | 增加依赖与配置；M0-M1 阶段自研 40 行足够可控 |
