# ADR-003：写操作必须人工确认，模型无权自确认

- 状态：已接受
- 日期：2026-11-17

## 背景

Agent 的典型事故不是"答错"，而是"做错"：批量补签、错误请假、误删课堂。模型一旦能直接调用写接口，一次幻觉就是一次数据事故。

## 决策

1. 模型只能调用 `propose_*` 生成**待确认动作**，返回 `action_id` 与摘要，**不返回确认令牌**。
2. 确认令牌只通过人工通道（HTTP 接口 / 未来 UI）获取；执行必须满足：令牌正确 + 状态为 `confirmed`。
3. 每个动作带**幂等键**（任务 + 学生集合），重复提议返回同一个动作。
4. 执行结果与确认过程写入**审计日志**；重复执行返回首次结果（幂等）。
5. 写操作**永不自动重试**（`read_only=False` 时 registry 只尝试一次）。

## 理由

- 把"模型能力"限制在"提议"，把"决定权"留给人
- 令牌不进入模型上下文，模型无法自导自演"提议→确认→执行"
- 幂等与审计保证重试、超时、重复点击都不会产生重复业务

## 后果

正面：
- 最坏情况是"提议错误"，人工可拦
- 审计可回答"谁在什么时候依据什么补签了谁"
- 面试可直接展开"Agent 安全边界"

负面：
- 多一次人工确认，效率略降（可接受，写操作低频）
- 需要额外的 UI/接口承载确认流程

## 替代方案

| 方案 | 为何不选 |
| --- | --- |
| 模型可直接写业务接口 | 幻觉即事故，不可接受 |
| 令牌随提议返回给模型 | 模型可自行确认，HITL 形同虚设 |
| 只读 Agent + 人工另开页面操作 | 丢失"提议→确认→执行"闭环价值 |
