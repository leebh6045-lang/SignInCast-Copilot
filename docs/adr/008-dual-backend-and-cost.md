# ADR-008：双模型后端对比与成本优化策略

- 状态：已接受
- 日期：2026-11-18

## 背景

M3 要求"质量可度量、成本可对比"。需要回答三个问题：
1. 同一个 Agent 换模型后，工具调用质量、延迟、成本差多少？
2. 哪些工程手段能让成本下降而不伤质量？
3. 如何避免"改一处、坏一片"？

## 决策

1. **双后端对比**：同一套 30 条用例，分别用 `deepseek-flash` 与 `deepseek-v4-pro` 跑子集（10 条），
   记录完成率、工具精确率/召回率、平均步数、P95 延迟、tokens、judge 分数。
   模型通过 `--model` 覆盖，不改代码。
2. **降本手段（可配置、可度量）**：
   - `COPILOT_RAG_TOP_K`：检索返回条数（默认 5，可降到 3）——直接减少引用文本 tokens
   - `COPILOT_ENABLE_TOOL_CACHE`：单次运行内只读工具结果缓存——减少重复调用与延迟
   - `COPILOT_TOOL_RESULT_MAX_CHARS`：工具结果字符上限——控制上下文膨胀
   - 上下文压缩（已有）：预算内优先丢弃冗余历史
3. **度量方式**：`eval/model_eval.py` 输出每个用例的 steps/tokens/latency/cost，
   汇总平均与 P95，并与 `eval/reports/baseline.json` 自动对比。
4. **默认配置**：取"优化后"配置（`rag_top_k=3` + cache 开），基线仅用于回归对比。
5. **反思机制**：回答校验失败或同一工具重复失败时，注入一轮反思提示（`app/runtime/reflector.py`），
   trace 记录 `reflection` 事件；不做无限重试。

## 理由

- 模型选型必须用数据说话，且对比脚本要能复用同一套用例，否则换模型就是拍脑袋。
- 降本优先做"无损/近无损"手段（减少冗余上下文、缓存、截断），而不是换更差的模型。
- 回归基线让"微调提示词/工具描述"这类高频改动有安全网。

## 后果

正面：
- 模型切换、检索参数、缓存开关都可量化对比
- 成本优化有前后数据，可写进报告与简历

负面：
- 评测有随机性，单轮结果只能看趋势（写进 limitations）
- judge 与 Agent 同模型，存在自评偏差
- 子集对比不能外推到全量

## 替代方案

| 方案 | 为何不选 |
| --- | --- |
| 只用最强模型 | 成本高，无法回答"贵多少、值不值" |
| 只用最便宜模型 | 工具调用质量风险不可见 |
| 不建基线，凭感觉调 | 无法发现回归 |
