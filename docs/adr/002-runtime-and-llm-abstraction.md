# ADR-002：自研轻量运行时 + 模型抽象层

- 状态：已接受
- 日期：2026-11-17

## 背景

Agent 主循环可以用现成框架（LangChain / LangGraph），也可以自己写。项目同时需要：离线可跑、可测试、可解释、可替换模型。

## 决策

1. **主路径自研轻量运行时**（约 300 行，`app/runtime/loop.py` + `context.py`），不依赖编排框架。
2. **模型通过 `ChatModel` 协议隔离**：`FakeChatModel`（离线/测试）、`OpenAICompatibleModel`（OpenAI 兼容接口，含 DeepSeek/Ollama）。
3. 框架对照实验放到 M3（用 LangGraph 重写同一场景，比较可维护性与可观测性）。

## 理由

1. **可讲透**：面试与复盘中，"为什么这么设计"必须能回答到代码行；框架黑盒会削弱这一点。
2. **可控**：HITL、预算、检查点、trace 都需要在循环内精确插入，自研改造成本更低。
3. **可测试**：`FakeChatModel` 让循环、工具、失败路径全部离线可测；框架往往需要真实模型才能跑。
4. **依赖少**：M0 只依赖 pydantic / httpx / fastapi，升级风险低。
5. **不排斥框架**：M3 做对照，如果 LangGraph 在复杂编排上明显更优，再迁移并记录原因。

## 后果

正面：
- 循环行为完全可控、可观测、可测试
- 换模型不影响业务代码
- 离线演示（无 API Key）成为可能

负面：
- 少了框架生态（内置 memory、callbacks、可视化）
- 复杂分支编排需要自己实现（M2 若膨胀，需评估迁移）

## 替代方案

| 方案 | 为何不选 |
| --- | --- |
| 直接用 LangChain/LangGraph | M0 阶段黑盒成本高；测试依赖模型；HITL 定制不顺手 |
| 用 Coze/Dify 等平台搭建 | 无法体现工程能力；私有化与评测受限 |
